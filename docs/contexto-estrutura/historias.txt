## Análise geral do projeto

### Arquitetura
- Frontend: React + TypeScript + Vite + Tailwind + `react-query`
- Backend: Node.js + Express + Prisma + PostgreSQL
- Autenticação: JWT com rotas separadas para paciente e sistema
- Repositório dividido em:
  - src para frontend
  - server para backend

### Pontos fortes
- Boa separação entre `frontend` e `backend`
- Uso de `helmet()` e `express-rate-limit` no backend
- Middleware de autenticação/autorizaçao em auth.js
- `AuthContext` e `axios` configurados para armazenamento de token e logout automático em 401/403
- index.js valida `JWT_SECRET` ao iniciar, evitando execução insegura
- Prisma usado para modelar dados com várias entidades e relacionamentos

### Observações importantes
- O backend expõe rotas em `/api/*`, mas index.js usa `app.use("/api", medicamentosRoutes)` em vez de `/api/medicamentos`. Isso pode gerar confusão ou rotas não intencionais.
- O `AuthContext` usa `localStorage` para token e usuário; bom para fluxo básico, mas em produção vale considerar `httpOnly` cookies para diminuir risco XSS.
- A `baseURL` do axios está fixa em `http://localhost:3001/api` em api.ts, então o deploy precisa ajustar essa variável ou usar env vars no frontend.
- O index.js já evita servar uploads estáticos publicamente, o que é uma boa prática.

### Possíveis melhorias
- Centralizar variáveis de ambiente do frontend para `VITE_*` em vez de baseURL hardcoded
- Adicionar validação de entrada mais forte nas rotas `auth` e nos controllers do backend
- Rever se todas as rotas `api/*` estão nomeadas de forma consistente
- Verificar `prisma/schema.prisma` para possíveis campos de timestamp faltantes em tabelas adicionais e normalização de relacionamentos
- Considerar uso de `express.json({ limit: '10mb' })` com atenção ao upload de arquivos grandes
